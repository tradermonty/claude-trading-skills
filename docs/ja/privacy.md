# プライバシーとデータ管理

これはリポジトリの運用方針です。入力がすべて端末内に留まるという保証ではありません。
個人の取引データを使う前に、スキルの処理、ツール権限、接続先の規約を確認してください。
口座識別子、保有明細、税務資料、APIキー、未加工の会話は、意図した開示でない限り、
公開サンプル、Issue、PR、モデルへの入力に含めないでください。架空の例に置き換え、
識別情報を除き、派生した文章も確認してください。切り詰めは匿名化ではありません。
全般的なPII（個人識別情報）の自動除去機構はありません。
レポート、ログ、事後検証を共有する前に、氏名、口座番号、注文ID、ブローカー識別子を
架空のラベルに置き換え、自由記述、ファイル名、メタデータにも識別情報がないか確認します。
レビューに必要な項目だけを共有してください。

## ローカル保存とGitの境界

| 場所 | 保存され得る情報 | 扱い |
| --- | --- | --- |
| `state/theses`、`state/journal` | 投資仮説、保有、判断、取引結果 | 非公開。変更前にバックアップ |
| `reports/`、`reviews/` | ポートフォリオ分析、生成レポート、レビュー結果 | 原則非公開。共有前に内容を確認 |
| `logs/`、`.cache/`、`.staging/` | 診断、プロバイダー応答、自動化状態、中間生成物 | 機微な応答やエラー抜粋を含む可能性 |
| `.env`、`.env.*`、`.envrc*`、`.mcp.json*`、`.aws/`、`.ssh/` | 認証情報、ローカル接続設定 | OSのアクセス権で保護。公開禁止 |
| `.claude/`、`~/.claude/projects/` | エージェント設定、会話履歴 | ユーザー入力・ツール応答を含む。マイニングの説明を参照 |
| `private-backups/` | 復旧用コピー、ハッシュ一覧 | アクセス制限。端末外のコピーは暗号化 |

ルートの [`.gitignore`](https://github.com/tradermonty/claude-trading-skills/blob/main/.gitignore)
は、これらのリポジトリ内の標準保存場所を除外します。
[`check_private_data_paths.py`](https://github.com/tradermonty/claude-trading-skills/blob/main/scripts/check_private_data_paths.py)
は、実際のGitインデックスに含まれるルートの `state`、`reports`、`logs`、`reviews`、
`.cache`、`.claude`、`.staging`、`private-backups`、`.aws`、`.ssh`、dotenv・`.envrc` 系、
`.mcp.json` 系のパスを拒否します。強制追加と大文字小文字の違いも対象です。
例外は、正確に一致する通常ファイルで、インデックス上でも空の
`state/journal/.gitkeep` と `state/theses/.gitkeep` のみです。
pre-commitと既存のルートスクリプトCIテストで確認します。貢献前にフックを導入してください。
CIは、すでにpushされた秘密を取り消すものではありません。

このガードが確認するのはパス名とGitオブジェクトのメタデータです。
`examples/`、`docs/`、テスト配下の確認済み架空データは許可され、そこに置かれた実データを
内容から検知する機能はありません。ignoreは暗号化、履歴削除、アップロード防止、
リポジトリ外の絶対パスの保護にはなりません。別のdetect-secretsフックもMarkdown、JSON、CSV
などを除外しており、秘密・PIIの完全な検査ではありません。キーが漏れた場合は接続先で
失効・ローテーションし、履歴や生成物への影響も別途確認してください。

## 外部へのデータフロー

| 接続 | 送信・参照されるデータ | 応答と境界 |
| --- | --- | --- |
| FMPクライアント | 銘柄、日付、条件、APIキー（エンドポイントに応じヘッダーまたはクエリ） | 市場データ。生の応答がキャッシュ・出力に残り得る |
| FINVIZ | スクリーニング条件、設定した認証キー | 検索結果 |
| Alpacaツール・ポートフォリオ全体のワークフロー | ブローカー認証による口座・保有照会。応答がモデル文脈に入る可能性 | 口座・保有データ。ローカルCSV比較・正規化コマンドはオフラインだが、別ツール接続で境界は変わる |
| WebSearch・ブラウザ | 検索語、銘柄、検索文に含めた入力 | 外部ページ。検索語に口座情報を含めない |
| Claude・設定したモデル | 会話、貼付ファイル、文脈に選ばれたツール応答、下記マイニング・レビュー用プロンプト | モデル出力。接続先の保持・アクセス設定も確認 |
| GitHub自動化 | 選択した候補、スキル変更、PR文、コミットしたファイル | 公開され得る。派生物や成果物も公開前に確認 |

通信の保護は設定したエンドポイントとツールに依存します。HTTPSを使い、キーをログや
プロンプトに記載しないでください。すべての通信経路に自動マスキングがあるわけではありません。
ブローカー利用に関するスキルの指示は、あらゆる注文実行を技術的に遮断する仕組みではありません。
実際のツール機能・権限を確認してください。オフライン処理は外部接続ツールの利用許可を意味しません。

## 会話履歴マイニングは個別に判断

[`mine_session_logs.py`](https://github.com/tradermonty/claude-trading-skills/blob/main/skills/skill-idea-miner/scripts/mine_session_logs.py)
は、選択した `~/.claude/projects/` のプロジェクトディレクトリ直下の `*.jsonl` を読みます。
通常は更新日時が過去7日以内のファイルです。既定の対象は `claude-trading-skills`、
`claude-market-agents`、`trade-edge-finder`、`trade-strategy-pipeline`、`weekly-trade-strategy`
です。`--project` 指定は対象を変更・拡張できます。すべてのCodex履歴フォルダーを走査する処理ではありません。

外部ユーザーメッセージ、assistantのツール名・入力、ツール結果・エラーを解析して兆候を抽出します。
サイドチェーンと不正なレコードはスキップします。モデル向けプロンプトにはプロジェクト名、
パターン、選ばれたユーザー抜粋最大5件（各200文字）、各兆候のサンプル最大3件（各100文字）
が入り得ます。`claude -p` に標準入力で渡し、最大3ターン、予算1米ドル、タイムアウト600秒で
実行します。この制限は匿名化ではありません。個人情報を含む履歴で実行する前に、同意と内容を確認してください。

`--dry-run` はモデルによる抽象化を省きますが、ローカル履歴の読取・解析と派生候補の保存は行います。
生候補やセッション詳細にも機微な内容が残り得ます。
[週次生成パイプライン](https://github.com/tradermonty/claude-trading-skills/blob/main/scripts/run_skill_generation_pipeline.py)
はマイナーを呼び出し、後続の生成・バックログ・PR処理で派生物が公開される場合があります。
[改善ループ](https://github.com/tradermonty/claude-trading-skills/blob/main/scripts/run_skill_improvement_loop.py)
もスキル・レビュー用プロンプトを `claude -p` に送ります。どちらもPII除去を保証しません。
スケジュールを停止するだけでは、既存の履歴や生成物は消えません。

## 保持方針と現在の自動処理

運用上の目標は、通常の診断ログは30日以内、レポート・履歴抜粋は必要最小限とし、
調査証跡はレビュー・復旧に必要な期間だけ保持することです。不要な非公開ファイル・コピーは
運用者が確認して削除し、削除前にバックアップの必要性を確認します。
プロバイダー側の保持期間は、接続先・アカウント設定に従う別の問題です。

現在の実装では、生成・改善スクリプトが削除するのは `logs/` 直下の30日を超えた `*.log`
のみで、それぞれの状態履歴は60件に制限されます。下位ディレクトリのログ、JSON状態、レポート、
キャッシュ、Claude履歴、バックアップには、**統一された自動削除はありません**。
方針を実装済みの機能として扱わず、作業中・未確認の証跡に一括削除を実行しないでください。

復旧訓練には[検証対象のバックアップ・復元手順](https://github.com/tradermonty/claude-trading-skills/blob/main/docs/dev/thesis-backup-restore.md)
を使います。書込み停止、非公開の保存先、新規出力先、全ファイル一覧・SHA-256の一致、
読取り専用 `doctor` の成功を確認します。テストは架空データの元ファイル喪失後に復元するもので、
利用者自身のバックアップを保証しません。
[SECURITY.md](https://github.com/tradermonty/claude-trading-skills/blob/main/SECURITY.md)
に報告経路の制限とサポート方針を記載しています。ここでの機能記述は2026-11-14のソース確認に基づき、
公開サイトの反映状況・プロバイダー設定とは異なる場合があります。
